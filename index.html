Field notes

A password's real strength is its entropy — roughly, how many guesses an attacker would need on average before landing on it. Entropy grows with two things: how many symbols could appear in each position, and how many positions there are. Adding a fifth character set matters less than adding five more characters.

This tool draws every character with crypto.getRandomValues, the browser's cryptographically secure random source — unlike the plain rand() found in a lot of hand-rolled generators, which is predictable enough that it shouldn't be trusted for anything security-sensitive.

Field notes

Length beats cleverness. Four unrelated words, even with no substitution at all, comfortably out-entropy a short password crammed with symbols — because each additional word multiplies the guess-space, while a single extra symbol only nudges it. This is the idea behind diceware-style passphrases.

The letter substitutions here (a→@, e→3...) are mostly cosmetic — attackers' dictionaries already account for them. They're included because they make a phrase feel less guessable to a human reader, and because mixing in digits and symbols satisfies password rules that still require them. The real work is done by the word count.

Field notes

"Online, throttled" assumes an attacker guessing through a login form that limits attempts — roughly 100 tries a second. "Offline, fast hardware" assumes they've already obtained a database of password hashes and are cracking them on GPUs, at roughly 10 billion guesses a second. The gap between those two numbers is why a leaked, unsalted password database is so much more dangerous than a login form with rate-limiting.

No score here can tell you if a password has appeared in a breach before. For that, a service like Have I Been Pwned checks a password against real leaked databases without ever sending it over the network in full.
